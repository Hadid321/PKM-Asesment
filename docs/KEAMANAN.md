# Batas kepercayaan dan keputusan database

Paket tiga mapel disimpan dalam modul `server-only`. Halaman `/paket-soal` dan unduhan `/api/paket-soal` memeriksa peran guru di server; respons CSV memakai `private, no-store`. Paket tidak berada di `public/`. Aksi `import-curriculum` juga memeriksa peran serta peninjauan, menulis pembuat dari sesi, dan melewati fingerprint duplikat. Siswa hanya menerima DTO soal yang sudah dipilih. Metadata mapel/kategori tetap setelah topik dibuat, dan prasyarat lintas mapel ditolak di aplikasi serta trigger database.

Pembaruan bank sekolah: siswa hanya menerima soal milik guru yang kelasnya diikuti. Soal seed dengan created_by NULL dipertahankan, tetapi dikeluarkan dari bank aktif. Guru hanya melihat/mengelola soal miliknya. Migration `20261023123926_teacher_managed_question_bank.sql` menambahkan pembatasan snapshot, policy guru dan trigger validasi soal sesi tanpa mengubah skema lama atau menghapus data. Lihat [panduan pembaruan](UPDATE-SEKOLAH.md).

Delapan tabel inti tetap tersedia: profiles, classes, class_members, topics, topic_prerequisites, questions, attempts, mastery. Ditambah `quiz_sessions` untuk soal aktif, batas sesi, penyelesaian dan klaim penjelasan; `private.app_revision` untuk satu lock transaksi yang menjamin snapshot tidak usang. Tidak diperlukan tabel kunci terpisah karena **siswa tidak memiliki policy SELECT atas questions sama sekali**. Semua akses siswa ke soal melalui DTO allowlist server yang hanya berisi id, topic_id, question_text, empat options, difficulty.

Semua tabel public memakai RLS, grant eksplisit, FK, check/unique constraints dan indeks relevan. Client authenticated mendapat SELECT sesuai RLS dan UPDATE hanya kolom full_name pada profil sendiri. Tidak ada grant write untuk role, kelas, attempts, mastery, soal atau sesi. Trigger signup selalu membuat student tanpa membaca metadata role. Penghapusan relasional memakai RESTRICT untuk menjaga riwayat; operasi penghapusan penelitian harus ditinjau administrator.

RLS mengizinkan siswa membaca profil dan asesmen sendiri. Guru membaca kelas miliknya dan hasil siswa yang **saat ini tergabung** dalam salah satu kelasnya. Riwayat siswa itu mencakup seluruh latihan topik yang tersedia, bukan hanya latihan yang dimulai setelah join; kebijakan ini dipilih agar guru dapat mendampingi penguasaan terkini dan harus dijelaskan saat persetujuan uji. Tidak ada endpoint keluar kelas pada MVP.

Helper SECURITY DEFINER hanya berada di schema private, memakai search_path kosong dan auth.uid() terverifikasi untuk lookup membership sehingga tidak terjadi rekursi RLS. Trigger auth memiliki tugas terbatas membuat profil student. RPC transaksi public adalah SECURITY INVOKER; EXECUTE direvoke dari PUBLIC/anon/authenticated dan diberikan hanya kepada service_role.

Server memanggil `auth.getUser()` untuk memastikan identitas terkini, membaca role profiles dari database, lalu mengakses adapter administratif. Proxy hanya refresh/verifikasi token, bukan satu-satunya pagar otorisasi. Setiap endpoint administratif memanggil requireActor sebelum repository. Operasi domain mengulangi pemeriksaan peran, kepemilikan soal, dan sesi. Client tidak boleh mengirim student_id, teacher_id, p_l, is_correct, atau role; Zod strict menolak field tambahan. Tidak ada admin endpoint promosi guru.

Snapshot Supabase hanya memuat kelas, siswa, jawaban dan bank soal yang diperlukan aktor. Server menghitung perubahan secara murni. RPC commit mengunci private.app_revision, membandingkan revision, memeriksa aktor/kepemilikan, menyimpan semua perubahan dan menaikkan revision dalam transaksi yang sama. Jika revision sudah berubah, adapter mengulang pembacaan dan perhitungan maksimal lima kali. Jawaban ganda terdeteksi oleh pasangan session_id–question_id pada domain dan unique constraint database; transaksi keduanya tidak menghitung BKT dua kali. Mastery tidak dapat diperbarui lewat commit tanpa percobaan terkait. RPC memverifikasi sesi aktif, soal yang diterbitkan dan hasil benar/salah terhadap kunci database.

Snapshot kunci, pilihan dan pembahasan hanya disimpan/dikembalikan setelah penilaian terhadap jawaban milik siswa itu. Siswa tidak menerima jawaban teman. Riwayat mempertahankan kunci dan penjelasan terdahulu jika guru mengedit soal. Bank aktif hanya berisi soal guru pemiliknya; konten seed tanpa pemilik tidak ditampilkan sebagai bank guru atau latihan siswa. Deteksi duplikat berlaku pada soal yang sudah dimiliki guru saat mengunggah.

Route mutasi membatasi request stream 600 KB, memvalidasi Origin terhadap APP_URL, memakai cookie SameSite, validasi input server dan rate limit proses. CSV maksimal 500 KB/200 soal, teks dibatasi panjang dan tautan hanya HTTPS atau materi lokal. Rate limit login pada multi-instance tetap perlu pengaturan Supabase Auth/platform. Session limit 12/jam dan satu sesi aktif bersifat tersimpan/transaksional, bukan hanya memori. CSP ketat belum ditambahkan karena perlu penanganan nonce Next.js; header nosniff, DENY frame, referrer dan permissions tersedia.

Groq tidak menerima identitas, memakai satu klaim persisten per sesi, timeout dan retry nol. Template tersedia sebelum panggilan eksternal. Key dan provider errors tidak dicatat ke console atau diteruskan kepada siswa. Tidak ada secret di NEXT_PUBLIC, seed, template CSV atau laporan. File demo dan .env.local diabaikan Git. .env.example hanya placeholder.

PGlite memverifikasi SQL/RLS dengan role PostgreSQL dan stub auth.uid(), tetapi belum menjalankan Auth, PostgREST, advisory Supabase atau konfigurasi hosted. Sebelum uji sekolah, jalankan skenario eksternal pada docs/VERIFIKASI.md dan Security Advisor pada proyek Anda. Pembatasan instance demo dan katalog topik bersama adalah keputusan MVP yang disengaja.
